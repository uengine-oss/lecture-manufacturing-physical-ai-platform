Skill 은 업무 지침, SOP 는 근거, 도구는 실행 기능

SKILL.md 에 승인 규칙을 썼다는 것만으로 승인 검사가 구현되지는 않는다. 검사는 도구의 코드가 한다.

Skill · SKILL.md

무엇을 어떤 순서로 판단하나

  • 센서 품질 확인 → 대상 설비 → SOP 검색 → 제안 → 승인 확인 → 실행 → 재측정
  • 인용 규칙: 검색 결과에 실제로 나온 절만
  • 중단 규칙: 근거 없으면 HOLD, 센서 오류면 SENSOR_CHECK
  • 짧게(수업용 1.6천 자) · 에이전트가 실행 시 로드

SOP · 문서 근거

무엇이 허용되고 누가 승인하나

  • 5종: 센서 오류 점검 · 냉각 이상 확인 · 승인 부하 감소 · 조치 후 재점검 · 미개선 이관
  • 같은 양식: 적용 설비 · 발동 조건 · 확인할 관측 · 허용 조치 · 승인 주체 · 재점검 기준
  • 문서 ID·버전·유효일 → 긴 본문은 검색 도구로 불러온다

도구 · 실행 기능

실제로 조회하고 실행하고 검사한다

  • DB·그래프 조회, 시뮬레이터 조치, 재측정 판정
  • 허용 조치·값 범위·승인 기록·사건 유효성·중복 키를 코드에서 확인
  • LangChain 도구 · MCP 서버 · 플랫폼 프로세스가 같은 함수를 공유
도구입력결과와 제한누가 호출하나
get_asset_contextasset_id센서 · 적용 SOP · 허용 조치(값 범위)에이전트
get_recent_windowasset_id, 기간관측 요약 · 단위 · 품질 플래그 — 원시 배열은 주지 않는다에이전트
search_sopasset_id, event_type문서 ID · 버전 · 절 · 근거 본문 (설비·active 필터 + 그래프 확인)에이전트
propose_actionevent_id, 근거 참조제안과 허용 범위 검사 결과 — 실행하지 않는다에이전트
execute_sim_actionevent_id, 승인 ID, 조치값승인 테이블 기록을 검사한 뒤 실행하고 결과 기록오케스트레이션(승인 후)
verify_recovery조치 ID, 재측정 기간회복 · 미개선 · 데이터 부족오케스트레이션
