## 이번 회차에서 할 일

1회차에서 만든 B1→B2→B3 경로는 제공 품질 검사기를 그대로 썼다. 오늘은 그 검사기의 내부 조건을 직접 고친다. 센서가 값을 보내지 않거나(결측), 한 번 튀거나(급등), 같은 값에 멈추는(고착) 일은 설비가 고장 난 것과 다르다. 이 차이를 구별하지 못하면 뒤 회차의 감지(B5)가 센서 배선 문제에 부하 감소를 제안하거나, 반대로 실제 냉각 저하를 "급등"으로 지워 버린다. 회차가 끝나면 오류 주입본과 시뮬레이터 시나리오에서 결측·급등·고착을 서로 다른 플래그로 나누고, 원시 값·정제 값·플래그를 함께 저장하고, 구간을 "센서 오류 / 설비 이상 / 정상"으로 표시할 수 있다.

### 학습 목표
- 오류 주입본(사이클 #1500)의 결측·급등·고착을 플래그 분포와 위치로 설명한다.
- `QualityRules` 기준(gap_hold_s=5, stuck_run=8, spike_delta TS1=8°C)에 맞게 결측·고착·급등 조건과 1초 집계를 고치고 테스트로 검증한다.
- 원시 값(`raw_value`)을 보존하고 정제 값(`value`)만 비우는 저장 규칙을 SQL 로 확인한다.
- 센서 오류 구간에서 설비 이상 판정을 보류하는 순서를 코드로 구현한다.

## 2. 핵심 개념

### 2.1 원시 값과 정제 값

`hydops/b2_quality/checks.py` 의 원칙은 파일 첫머리에 적혀 있다.

```python
# lecture/system/hydops/b2_quality/checks.py (발췌)
"""B2 · 센서 품질 검사.

센서 오류(결측·급등·고착·범위 이탈)와 설비 이상을 구분하기 위해 관측마다 품질 플래그를 붙인다.
원시 값(raw_value)은 그대로 보존하고, 정제 값(value)은 품질이 OK 일 때만 채운다.
긴 결측을 보간해서 정상 값처럼 숨기지 않는다.
"""
OK, MISSING, GAP, SPIKE, STUCK, OUT_OF_RANGE = "OK", "MISSING", "GAP", "SPIKE", "STUCK", "OUT_OF_RANGE"
```

| 플래그 | 조건 (TS1 기준) | 정제 값 | 뒤 블록의 해석 |
|---|---|---|---|
| OK | 아래 어느 것도 아님 | 원시 값 | 설비 판단에 쓴다 |
| MISSING | 결측 1~4초째 | NULL | 짧은 결측, 지속 카운터 유지 |
| GAP | 결측이 5초째 이상 | NULL | 판정 보류 → SENSOR_FAULT |
| STUCK | 같은 값 8번째 반복부터 | NULL | 판정 보류 → SENSOR_FAULT |
| SPIKE | 직전 유효값과 1초 사이 8°C 초과 점프 (3회 연속이면 OK) | NULL | 단발은 기록만 |
| OUT_OF_RANGE | -10°C 미만 또는 120°C 초과 | NULL | 물리적으로 불가능 |

### 2.2 오류 주입본

![오류 주입본의 플래그](../../materials/figures/F03_quality_flags.png)

사이클 #1500 에 `uci.inject_sensor_errors` 로 급등 1건(+25°C), 결측 7초, 고착 10초를 넣은 결과다. 회색 굵은 선이 원시 값, 파란 선이 정제 값이다. 결측 7초 중 앞 4초는 MISSING, 5초째부터 GAP 이다. 고착 10초 중 STUCK 은 3초뿐인데, 같은 값이 8번째 나올 때 비로소 "고착"이라 판정하는 스트리밍 방식이라 앞 7초는 OK 로 지나가기 때문이다.

> **주의** — 고착 앞 7초가 OK 로 저장되는 것은 버그가 아니라 스트리밍 판정의 지연이다. 나중에 되돌아가 앞 7초를 고쳐 쓰지 않는다. 대신 구간 판정(`classify_window`)이 STUCK 이 하나라도 있으면 구간 전체를 SENSOR_FAULT 로 본다. 이 선택이 맞는지는 회고에서 토론한다.

## 4. 활동 2 — 품질 기준과 1초 집계 수정 · 50분

### 목표
`labs/practical/S02/quality.py` 의 `aggregate_1s` 와 `LabQualityChecker.check` 를 기준에 맞게 고친다.

### 따라 하기
이 활동의 비교 출력은 시작본(`st`)과 정답본(`sol`)을 함께 불러와 실행한 것이다.

```python

    spec = importlib.util.spec_from_file_location(name, path)
    mod = importlib.util.module_from_spec(spec); spec.loader.exec_module(mod); return mod
```

1. **1초 집계.** 고주파 센서는 1초 안의 일부 샘플만 빠질 수 있다. 시작본은 결측을 0 으로 채운다.

   ```python
   # lecture/labs/practical/S02/quality.py (시작본 발췌)
   for sec in shaped:
       # TODO(학생): 결측 샘플(NaN)을 0 으로 채우고 n 을 hz 로 고정한다. ...
       filled = np.nan_to_num(sec, nan=0.0)
       out.append({"mean": float(filled.mean()), "min": float(filled.min()), "max": float(filled.max()), "n": hz})
   ```

   사이클 #100 PS1 의 6초째 100개 샘플 중 앞 70개를 NaN 으로 만들고(`smp[600:670] = np.nan`) 비교한 결과다. 이 절의 출력 앞머리 `starter`/`solution` 은 실행한 모듈(시작본/정답본)을 표시하고, `full mean sec6` 은 남은 30개 샘플(`smp[670:700]`)의 평균이다.

   ```
   starter   PS1 sec6 (70 NaN): {'mean': 56.9979, 'min': 0.0, 'max': 190.23, 'n': 100} full mean sec6 189.99300000000002
   solution  PS1 sec6 (70 NaN): {'mean': None, 'min': None, 'max': None, 'n': 30} full mean sec6 189.99300000000002
   ```

   남은 30개 샘플의 평균은 189.99 bar 인데, 0 으로 채운 평균은 57.00 bar 로 "압력이 급락한 것"처럼 보인다. 정답본은 유효 샘플만 세고(`n=30`), 유효가 hz×0.5 미만이면 그 1초를 결측(`mean=None`)으로 넘겨 품질 검사가 MISSING/GAP 으로 판정하게 한다.

2. **긴 결측.** 시작본은 결측을 항상 MISSING 으로 두고 정제 값을 직전 유효값으로 채운다.

   ```python
   # 시작본
   if raw is None:
       self._missing_run[key] += 1
       # TODO(학생): 결측이 아무리 길어도 MISSING 이고, 정제 값을 직전 유효값으로 채운다(forward fill). ...
       flag = MISSING
       self._same_run[key] = 0
       recent = self._recent[key]
       return {**row, "quality_flag": flag, "value": recent[-1] if recent else None}
   ```

   오류 주입본 24~33초를 시작본과 정답본으로 검사한 결과 (`(elapsed_s, raw_value, flag, value)`):

   ```
   starter   [(24, 35.516, 'OK', 35.52), (25, 35.426, 'OK', 35.43), (26, None, 'MISSING', 35.43), (27, None, 'MISSING', 35.43), (28, None, 'MISSING', 35.43), (29, None, 'MISSING', 35.43), (30, None, 'MISSING', 35.43), (31, None, 'MISSING', 35.43), (32, None, 'MISSING', 35.43), (33, 35.586, 'OK', 35.59)]
   solution  [(24, 35.516, 'OK', 35.52), (25, 35.426, 'OK', 35.43), (26, None, 'MISSING', None), (27, None, 'MISSING', None), (28, None, 'MISSING', None), (29, None, 'MISSING', None), (30, None, 'GAP', None), (31, None, 'GAP', None), (32, None, 'GAP', None), (33, 35.586, 'OK', 35.59)]
   ```

   시작본은 7초 결측 동안 35.43°C 가 이어진 것처럼 정제 값을 채운다. **긴 결측을 정상 값으로 숨긴 것**이다. 정답본은 `gap_hold_s` 이상에서 GAP 으로 바꾸고 정제 값을 비운다.

3. **고착.** 시작본은 `self._same_run[key] > self.rules.stuck_run` 이라 9번째부터 STUCK 이다. 10초 고착에서 STUCK 이 2개로 줄고 테스트가 `assert 2 == 3` 으로 실패한다. `>=` 로 고친다.

4. **급등과 수준 변화.** 시작본은 최근 유효값들의 중앙값과 비교하고, 연속 점프를 수준 변화로 받아들이지 않는다.

   ```python
   # 시작본
   elif recent and abs(raw - statistics.median(recent)) > self.rules.spike_delta.get(sid, float("inf")):
       self._spike_run[key] += 1
       flag = SPIKE
   ```

   정답본은 완성 시스템과 같다.

   ```python
   # lecture/system/hydops/b2_quality/checks.py (발췌) = S02 정답본
   elif recent and abs(raw - recent[-1]) > self.rules.spike_delta.get(sid, float("inf")):
       # 1초 사이에 물리적으로 불가능한 점프 → 급등. 단, 3회 이상 연속이면 수준 변화로 받아들인다
       self._spike_run[key] += 1
       flag = SPIKE if self._spike_run[key] < 3 else OK
   ```

   냉각 성능 0.25(시드 7) 시나리오 80초를 두 검사기로 돌린 결과다.

   ```
   starter   severe 0.25 flags: {'OK': 22, 'SPIKE': 58}
   solution  severe 0.25 flags: {'OK': 80}
   ```

   이 시나리오에서 1초 사이 최대 상승은 3.57°C 로 기준 8°C 보다 작다. 그런데 중앙값은 최근 몇 초 전 값이라 빠르게 오르는 온도보다 뒤처지고, 한 번 SPIKE 로 막힌 값은 `recent` 에 들어가지 않아 기준이 계속 낡는다. 결국 58개가 SPIKE 로 막힌다. 정제 값이 비면 B5 감지기는 유효 관측을 세지 못하므로 **실제 냉각 이상 사건이 생기지 않는다.** 완성 시스템을 만들 때 실제로 겪은 문제다.

### 확인 포인트
- 오류 주입본 분포가 정확히 `{'OK': 49, 'SPIKE': 1, 'MISSING': 4, 'GAP': 3, 'STUCK': 3}` 다.
- 45°C 대에서 60°C 대로 계단 변화하면 처음 두 값만 SPIKE, 세 번째부터 OK 다.
- 냉각 심각 저하의 빠른 상승에서 SPIKE 가 0 이다.

### 흔한 실수
- 급등 기준을 근거 없이 크게 올려(예: TS1 30°C) SPIKE 문제를 덮는다. FS1 을 15.0 으로 올린 것은 정상 사이클 실측 최대 10.94 L/min 이라는 근거가 있지만, TS1 의 정상 1초 최대 변화는 0.23°C 이므로 30°C 로 올릴 근거가 없다. 그러면 +30°C 에 노이즈가 더해지는 시뮬레이터 spike 주입도 기준에 따라 통과할 수 있고, 오류 주입본의 +25°C 급등은 확실히 통과한다. 비교 대상(직전 유효값)과 수준 변화 규칙을 고치는 것이 맞다.
- 1초 집계에서 NaN 이 섞인 배열에 `np.mean` 을 그대로 써 `nan` 을 만든다. `nan` 은 `None` 이 아니므로 품질 검사가 결측으로 보지 못한다.

## 6. 활동 4 — 설비 이상과 센서 오류를 다른 상태로 표시 · 50분

### 목표
`window_state` 를 고쳐 TS1 구간을 SENSOR_FAULT / EQUIPMENT_ANOMALY / NORMAL 로 나누고, 센서를 믿을 수 없을 때 설비 판정을 보류한다.

### 따라 하기
1. 완성 시스템의 구간 판정을 읽는다. 센서 오류 조건만 본다.

   ```python
   # lecture/system/hydops/b2_quality/checks.py (발췌)
   def classify_window(rows: list[dict], rules: QualityRules = QR) -> str:
       """구간이 '센서 오류'인지 판단한다. 센서 오류면 설비 조치를 보류한다."""
       q = window_quality(rows)
       if q["n"] == 0:
           return "NO_DATA"
       if q["longest_gap_s"] >= rules.gap_hold_s or q["flags"].get(STUCK, 0) > 0:
           return "SENSOR_FAULT"
       if q["valid_ratio"] < 0.7:
           return "SENSOR_FAULT"
       return "VALID"
   ```

2. 시작본 `window_state` 의 두 가지 잘못을 찾는다.

   ```python
   # 시작본
   for r in rows:
       # TODO(학생): 원시 값으로 센다. ...
       if r["raw_value"] is not None and r["raw_value"] > alarm_c:
           run += 1
           best = max(best, run)
       else:
           run = 0
   # TODO(학생): 설비 이상을 먼저 판정한다. ...
   if best >= sustain_s:
       state = EQUIPMENT_ANOMALY
   elif q["flags"].get(STUCK, 0) > 0 or q["valid_ratio"] < 0.7:
       state = SENSOR_FAULT
   ```

3. 경보 온도 위에서 센서가 고착된 시나리오(냉각 0.25 + stuck 15초)의 마지막 60초를 두 함수로 판정한다.


## 용어

| 용어 | 뜻 |
|---|---|
| 원시 값(raw_value) | 센서가 보낸 1초 값. 결측이 아니면 품질이 나빠도 보존한다 |
| 정제 값(value) | 품질 OK 일 때만 채우는 값. 감지는 이 값만 쓴다 |
| MISSING / GAP | 짧은 결측 / gap_hold_s(5초) 이상 이어진 결측. GAP 은 판정 보류 신호 |
| STUCK | 같은 값이 stuck_run(8)번째 반복된 순간부터의 고착 |
| SPIKE | 직전 유효값과 1초 사이 기준 초과 점프. 3회 연속이면 수준 변화로 받아들인다 |
| 수준 변화(level shift) | 값이 새 수준으로 옮겨가 유지되는 것. 급등과 구분한다 |
| 판정 보류 | 센서를 믿을 수 없어 설비 이상 여부를 판단하지 않는 상태 (SENSOR_FAULT → SENSOR_CHECK) |
| forward fill | 결측을 직전 값으로 채우는 보간. 긴 결측에는 쓰지 않는다 |
| 오류 주입본 | 사이클 #1500 에 급등 1·결측 7초·고착 10초를 넣은 교육용 데이터 |
